# Causal extraction v0.1.1 failure and redesign decision

Date: 2026-08-29

Status: accepted methodological decision; replacement instrument is not yet
frozen.

## Decision

The `v0.1.1-rc1` instrument is rejected for scientific extraction. Its raw
artifacts, prompts, schemas, runner revisions, and two checkpoint samples remain
frozen as instrument-development evidence. Candidate records, candidate counts
interpreted as causal-claim counts, and Levels from the checkpoints are barred
from the review synthesis.

The replacement instrument will use a causal analysis as its primary
classification unit. An atomic claim remains available as a derived
analysis-by-contrast view.

## Evidence for the decision

An independent `claude-opus-5` read-only audit was checked directly against the
frozen JSONL ledgers.

- Checkpoint A had no candidate for which all five runs produced a claim record.
  Its reported `20/20` Level agreement compared five empty lists for each
  candidate.
- Checkpoint B had one such candidate. Its five Levels were `3, 3, 3, 2, 3`.
- `duplicate_or_overlapping` accounted for 79/100 valid analysis-set responses
  in A and 65/80 in B. Candidate-status agreement therefore measured a
  deduplication problem created upstream.
- The exact payload hash included unconstrained prose, ordered arrays, split
  notes, and boundary descriptions. Five byte-equivalent outputs were not a
  scientifically meaningful acceptance target.
- Reports with incomplete grounded discovery held 1,141/1,288 candidates in A
  and 1,040/1,541 in B.
- Checkpoint A reused the 15-report codebook-development sample and was also
  used for prompt smoke testing. It is in-sample. B is disjoint but has no gold
  labels and cannot establish accuracy.

The corrected checkpoint report is
`analysis/causal_extraction/checkpoints/v0.1.1-rc1/two_sample_stability.md`.
The complete independent audit is
`analysis/causal_extraction/consultations/2026-08-29-opus5-v0.1.1-audit/report.md`.

## Replacement data model

### Report

One PRISMA-eligible publication. Store canonical document and section hashes,
source adequacy, organism, study type, and measured omics layers.

### Causal analysis

Primary extraction and classification unit: one identification strategy
applied to one exposure construct, one outcome construct, and one biological
system. Store design family, identifying variation, assignment mechanism,
contrast completeness, assumptions, diagnostics, omics roles, identification
assessment, and the Python-derived Level here.

Expected cardinality is approximately 1-8 analyses per report. This expectation
must be tested against expert annotation rather than enforced as a truncation.

### Reported contrast

Child of a causal analysis. Store endpoint, time point, stratum, effect or
logical contrast, estimate, uncertainty, and result direction. Contrasts do not
repeat the analysis-level identification assessment.

### Causal link

Cross-report dimension defined by exposure construct, outcome construct, and
system. It supports synthesis of independent analyses addressing the same link.

### Validation edge

Typed relation between two analyses or between an analysis and an external
dataset. Same-link alignment and independence are properties of this edge.
Level 4 is derived from these structured properties.

## Evidence contract

Canonical Docling text remains the source of record. Before model use, Python
will deterministically split it into stable evidence atoms with:

- `document_sha256`;
- `section_id` and `section_sha256`;
- `evidence_atom_id`;
- raw character start and end offsets;
- source order and, when available, page references;
- exact raw text and its SHA-256.

The model returns `evidence_atom_id` values and optional subspans. Python
resolves the exact quotation from frozen text. Generated quotation text cannot
become the citation of record. Unknown IDs, invalid offsets, and references
outside the supplied packet are deterministic failures.

This removes punctuation and OCR reproduction from the stability measure. It
does not establish that a selected passage scientifically supports a judgment;
semantic citation support must be measured against expert gold anchors.

## Model and Python responsibilities

The model classifies scientific text into closed values and points to evidence
atoms. Decision-driving fields include design family, identifying variation,
assignment, contrast flags, identification assessment, fixed assumption-status
vectors, diagnostic types, omics roles, result status, and structured
validation properties.

Free-text summaries and notes remain available for readers but are excluded
from exact-agreement gates and Python rules.

Python supplies IDs, document metadata, required assumption domains, and fixed
array order. It validates schemas, evidence references, referential integrity,
and logical consistency. It derives contrast completeness, validation status,
Levels, counts, and rule traces. Python does not interpret scientific prose or
semantically merge analyses.

## Repeat policy

The number of production repeats is unresolved. The old justification for five
runs came from unanimous exclusion during screening and does not automatically
transfer to post-eligibility extraction.

The development evaluation will compare fixed three-run and five-run policies
prospectively on the same gold-annotated analyses. Invalid technical attempts
remain reported and do not silently remove a unit from either denominator.
Adaptive stopping and seven runs are excluded from the first redesign cycle.

The user's strict stability objective remains: the selected production policy
must achieve exact repeated agreement on every registered decision-driving
enum, evidence-atom reference set, route, and derived Level. Free prose is not a
registered decision field.

## Smallest next experiment: E0

Run a grounding-contract bake-off before any new scientific classification.

- Sample: 6 reports from a newly declared development partition, stratified by
  document-size tercile and table density.
- Arms: legacy generated verbatim quotes versus deterministic evidence-atom
  identifiers.
- Repeats: 2 independent inventory runs per arm.
- Scope: inventory causal analyses and attach method/result evidence only. Do
  not assign identification judgments or Levels.
- Gold: two humans identify the analysis inventory and independently verify a
  stratified sample of at least 60 evidence references; disagreements are
  adjudicated before model scoring.
- Primary metrics: analysis-boundary precision/recall/F1, evidence-reference
  resolution, semantically supported-reference precision, silent omission,
  technical failure, candidates per report, and calls per report.
- Proceed gate: 100% resolvable registered evidence IDs, zero silently dropped
  windows, no fabricated citation text, semantic support precision at least
  0.98 in the audited references, and no loss of analysis recall relative to
  the legacy arm.

E0 isolates grounding from classification. A failure here stops the redesign
before expensive prompt ablations.

## Development and sealed evaluation

### Exposure-audit amendment, 2026-08-29

The conditional proposal to treat the 71 reports outside checkpoints A and B
as untouched was rejected after inspecting the earlier corpus-grounding pack.
Luna Light generated causal-analysis profiles for all 101 eligible reports;
four article-design agents reviewed all 101 profiles and inspected overlapping
full-text subsets. The 71 reports are outside the two checkpoints, but they are
not a genuinely sealed pool.

They may be used for development experiments with that exposure declared. E0
uses six such reports selected by document structure alone. A valid sealed
evaluation must instead use an external or temporal sample acquired after the
replacement prompts, schemas, code, runtime, acceptance thresholds, and Git
freeze are fixed. Checkpoint B remains unavailable for tuning or sealed claims.

The original proposed 24/30/17 internal split is withdrawn. This amendment is a
correction to the prospective design and does not reclassify prior outputs as
gold labels.

Two domain experts independently annotate analysis boundaries and
decision-driving fields before seeing model outputs. Inter-expert agreement is
reported first. If the human construct is not reproducible, revise the
codebook on development data and use the reserve set for the next sealed cycle.

## Required ablations after E0

1. Atomic claim versus causal-analysis unit.
2. Generated quote versus evidence-atom ID grounding.
3. Free text included versus excluded from the agreement hash.
4. Model-selected versus Python-supplied assumption-domain vectors.
5. Open inventory versus deterministic dense coverage audit.
6. Three versus five fixed repeats.

Each ablation uses the same development gold records, report-clustered
uncertainty estimates, explicit denominators, and a prespecified primary
metric. Only the selected final configuration is evaluated on the sealed set.

## Versioning consequence

Preserve codebook `v0.2.0` and prompt suite `v0.1.1-rc1` unchanged as rejected
lineage. The redesigned hierarchical codebook starts at `v0.3.0`; the matching
prompt suite receives a new version after E0 passes. No v0.1 scientific output
is migrated into the new ledger.
