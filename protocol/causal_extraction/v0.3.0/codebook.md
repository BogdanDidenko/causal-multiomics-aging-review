# Causal-analysis inventory codebook v0.3.0

## Scope

The review unit is one empirical aging report with at least two analytically
connected molecular omics layers. The extraction unit is one design-level
`causal analysis` reported in that paper. This codebook inventories analyses;
it does not infer biological truth from causal wording.

## Qualifying causal analysis

Include a current-report analysis only when all conditions hold:

1. The report presents an empirical result, including a null result.
2. The result concerns aging, lifespan, senescence, an age-related disease, or
   a mechanistic experiment that directly supports the report's aging link.
3. The analysis has either a named source of identifying variation or a formal
   directed-hypothesis method.
4. The analysis belongs to the report's multi-omics workflow. The causal test
   may use one assay when it validates a candidate generated by the integrated
   omics analysis.

Named identifying variation includes random assignment, a controlled
intervention, a genetic instrument, a genetic or molecular perturbation, a
surgical/model induction, a quasi-experimental assignment, or explicit
temporal identification. A formal directed-hypothesis method includes a named
mediation, DAG/SCM/SEM, Bayesian-network, Granger, or causal-discovery analysis
when effect identification remains insufficient.

## Exclusions

Do not create a causal analysis from any of the following by itself:

- causal or mechanistic wording;
- association, correlation, prediction, classification, or survival modeling;
- differential abundance or differential expression;
- enrichment, pathway direction, feature importance, or network centrality;
- an undirected correlation or protein-interaction network;
- colocalization without another identification design;
- an external study described in the introduction or reference list;
- a planned experiment or method with no current-report result;
- an intervention result unrelated to aging and unrelated to validation of the
  report's focal multi-omics aging link.

Colocalization, replication, rescue, reverse perturbation, and orthogonal
assays may be validation evidence for a qualifying analysis.

## Unit boundary

Use one analysis for one combination of:

1. source of identifying variation or assignment implementation;
2. exposure, intervention, instrumented trait, or perturbed target;
3. study population, dataset, or biological system.

Keep outcomes, molecular readouts, doses, time points, subgroups, and strata as
child contrasts when those three elements stay unchanged. A screen covering
many genes or outcomes under one shared instrument source and analytic
procedure remains one analysis. Opposite directions in bidirectional MR are
separate analyses. Different QTL layers or tissues are separate instrument
sources.

Gain- and loss-of-function experiments on the same target in the same system
form one analysis. A rescue or reverse perturbation can also be a separate
analysis when it introduces a distinct assigned intervention and reports a
direct aging or senescence outcome. It can simultaneously validate the
original link. Do not create a separate analysis for each molecule in an omics
table or network.

## Evidence anchors

Each analysis returns exactly one method atom and one result atom.

- `method_atom_id`: the earliest atom in document order that directly states
  the assignment, instrument, perturbation, intervention, or formal directed
  method for this unit. Prefer Methods text over a later restatement. A shared
  allocation atom may support multiple analyses.
- `result_atom_id`: the earliest atom in document order that directly reports
  an empirical result for this unit. A heading alone is insufficient.
- `validation_atom_ids`: zero or one atom. When validation qualifies, select
  the earliest atom that directly reports it.

Return atom IDs only. Python resolves exact quotes and rejects unknown IDs.
Sort analyses by method-atom document order, then result-atom document order.

## Controlled fields

`causal_basis`:

- `effect_identification_design`: intervention, instrument, perturbation, or
  another design intended to estimate an exposure-outcome contrast.
- `formal_directed_hypothesis`: a formal directed method proposes a testable
  causal structure without sufficient effect identification.

`design_family`:

- `genetic_instrument`
- `randomized_intervention`
- `nonrandomized_controlled_intervention`
- `targeted_perturbation`
- `mediation`
- `temporal_design`
- `graphical_or_structural_model`
- `causal_discovery_algorithm`
- `other_named_design`

`variation_source`:

- `randomized_assignment`
- `genetic_instrument`
- `genetic_perturbation`
- `molecular_perturbation`
- `pharmacologic_intervention`
- `behavioral_or_environmental_intervention`
- `surgical_or_model_induction`
- `temporal_ordering`
- `modeled_directionality`
- `other_named_source`

`aging_role`:

- `lifespan_or_longevity_outcome`
- `biological_or_chronological_aging_outcome`
- `cellular_senescence_outcome`
- `age_related_disease_or_decline_outcome`
- `mechanistic_support_for_aging_link`

`multiomics_role`:

- `omics_exposure_in_causal_design`
- `multiomics_outcomes_under_causal_design`
- `omics_candidate_followed_by_perturbation`
- `formal_cross_omics_directed_model`
- `report_level_multiomics_support`

`contrast_status`:

- `explicit`: exposure/intervention and comparator are stated.
- `implicit`: the design defines a contrast, but the comparator wording is
  incomplete.
- `unclear`: the available text does not define the contrast.

`assumptions_reviewability`:

- `reviewable`: the design and data source are sufficiently described to state
  and inspect the main identification assumptions.
- `partly_reviewable`: some essential design or data-source detail is missing.
- `not_reviewable`: the text does not permit an identification assessment.

`result_status`:

- `positive`
- `null`
- `mixed`

`validation_strength`:

- `none`
- `supportive_same_experiment`
- `link_specific_colocalization`
- `orthogonal_same_link`
- `independent_replication`
- `unclear`

## Deterministic evidence level

The model never returns a Level. Python derives it after validation:

- Level 2: `formal_directed_hypothesis`, or an effect design with an unclear
  contrast or nonreviewable assumptions.
- Level 3: `effect_identification_design` with an explicit or implicit contrast
  and reviewable or partly reviewable assumptions.
- Level 4: Level 3 plus link-specific colocalization, orthogonal validation of
  the same link, or independent replication.

Levels 0-1 remain report/context categories outside this qualifying-analysis
inventory. Stability and alignment with the analyst reference draft are
reported separately.
